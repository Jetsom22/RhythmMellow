# RhythmMellow — Godot

출시용 구현. Godot 4.7, GDScript. 웹으로도 내보내서 브라우저에서 해 볼 수 있다.

- 해 보기: https://jetsom22.github.io/RhythmMellow/godot/
- 설계: `../docs/superpowers/specs/2026-11-18-stage-system-design.md`
- 웹 프로토타입(`../src`)은 규칙의 정답지로 남긴다. 같은 씨앗이면 두 쪽이 같은 곡을 만든다.

## 스테이지 (2026-11-18)

첫 스테이지가 돈다. 구조는 레벨 디자인 세션의 `docs/level/stage-01.md`(2판)를 그대로 데이터로 옮긴 것이다.

| 파일 | 하는 일 |
|---|---|
| `core/meter.gd` | 박자표와 판정 |
| `core/shape_map.gd` | 도형으로 된 땅: 원, 캡슐, 사각형, 부채꼴, 다각형. 구멍은 땅보다 우선한다 |
| `core/sim.gd` | 규칙 전부. 그림도 소리도 없고, 지금 몇 초인지만 받는다 |
| `game/game.gd` | 화면과 소리. 규칙에서 나온 사건을 그림과 소리로 바꾼다 |
| `data/stages/stage-01.json` | 스테이지 데이터. 길이는 U(한 박 동안 걷는 거리) |
| `tools/build_stage01.py` | 위 데이터를 만든 스크립트. 배치를 바꿀 때 여기를 고치고 다시 돌린다 |
| `tools/test_sim.gd` | 규칙과 스테이지 데이터 검사 |

규칙:

- **판정은 둘이고 서로 다르다.**
  - **회피 대시(대시 판정)**: 박에서 판정 시간(`dashMs`, 지금 ±120ms) 안에 대시 키를 누르면 대시가 나간다. 그 밖에서는 아무 일도 없다. 나가면 항상 1U를 간다.
  - **저스트 회피(무적 판정)**: 회피를 시작한 순간이, 플레이어에게 떨어지는 공격의 판정 순간과 저스트 시간(`justMs`, 지금 ±60ms) 안에 겹치면 저스트다. 그 대시 동안 무적이다. 공격이 없으면 저스트도 없다.
  - 저스트가 아닌 대시는 누른 순간 아주 잠깐만 무적이라, 공격 범위 밖으로 나가야 산다.
- **맞거나 떨어지면** 목숨 하나를 잃고 두 박 동안 흩어졌다가 마지막 체크포인트에서 다시 모인다. 모인 뒤 한 박은 맞지 않는다. 흩어져 있는 동안에는 아무것도 플레이어를 겨냥하지 않는다.
- **악기를 얻으면** 목숨이 다 차고 저장된다. 목숨이 다하면 그 저장으로 돌아간다(스테이지 밖까지 남는 저장은 아니다).
- **공격하는 것은 모두 같은 엔진을 쓴다.** 장치, 몬스터, 수호자, 보스가 같은 공격 정의를 같은 방식으로 예약한다. 길에서 본 공격이 보스전에 그대로 나온다.
- **장치**는 정해진 마디를 되풀이하거나(`pattern`), 곡의 한 겹을 따라간다(`follow`: 베이스가 울리는 박마다 판정).
- **몬스터**는 박마다 플레이어 쪽으로 한 걸음 오는 장치다. `range` 밖에서는 공격하지 않는다.
- **수호자**는 공격해서 쓰러뜨리거나, 그 공격을 저스트로 연속 n번 피하면 통과한다(`advance.answered`).
- **공명판**은 맞는 악기를 든 채 한 마디 서 있으면 켜진다. 문은 깃발, 악기 개수, 특정 악기로 열린다.
- **보스**는 검증 빌드의 다섯 패턴을 크기와 박 그대로 쓴다.

주소 뒤에 붙여서 어디서든 시작할 수 있다: `?at=x,y`(U) `&parts=drum,hat` `&god=1`(맞지 않음) `&stage=이름` `&lab=1`(박 실험 화면).

아직 없는 것: 보스 직전의 공격 섞인 길, 메아리 선이 벽에 튕기는 표현, 검사기(처음 볼 때 하나만 / 보스 전에 다시 나오는가), 하드 모드(장비 교체).

## 실험 1: 고닷이 박을 지키는가 (`?lab=1`)

| 파일 | 하는 일 |
|---|---|
| `core/beat_clock.gd` | 게임의 유일한 시계. 박자표는 데이터로 받고, 타격의 격자와 회피의 격자를 따로 갖는다 |
| `core/rng.gd`, `core/song.gd` | 씨앗에서 곡 만들기. 웹과 결과가 같다 |
| `audio/synth.gd` | 겹마다 루프를 미리 구워 둔다 |
| `audio/mix.gd` | 믹싱: 목소리마다 EQ, 크기, 킥에 맞춘 베이스 낮추기, 공통 잔향. 설정은 `DESK` 표 하나 |
| `audio/mixer.gd` | 구운 루프들을 한꺼번에 틀고 겹을 켜고 끈다. 웹과 PC에서 내보내는 길이 다르다 |
| `audio/web_audio.gd` | 웹 전용: 루프를 브라우저의 오디오 스레드에 맡긴다 |
| `lab/lab.gd` | 실험 화면: 박을 보여 주고, 누른 박을 판정한다 |
| `main.gd` | 들어가는 곳. 기본은 게임, `?lab=1`이면 실험 화면 |
| `tools/run_tests.gd` | 화면 없이 도는 검사 |

## 박이 어긋나던 문제와 고친 것 (2026-11-18)

웹에서 박이 갈수록 어긋났다. 두 번 고쳤다.

**첫 시도: 고닷의 저지연 재생("sample").** 루프가 **끝난 뒤에야** 다시 트는 구조라서 한 바퀴마다 16~37ms씩 늦어지고 겹끼리도 20ms쯤 벌어졌다. 시계와 소리의 차이가 24초에 109ms 벌어졌다.

**둘째 시도: 엔진이 직접 섞는 재생("stream").** 화면 없는 시험 브라우저에서는 벌어지지 않았지만, 실제 기기에서는 여전히 벌어졌다. 웹에서는 엔진이 소리를 게임과 같은 스레드에서 섞는다. 그 스레드를 4배 느리게 만들어 보니 소리가 끊기고 차이가 크게 흔들렸다.

**지금: 웹에서는 브라우저의 오디오 스레드에 루프를 직접 맡긴다**(`audio/web_audio.gd`). 브라우저의 오디오 스레드는 샘플 단위로 정확히 되감고, 게임이 느려져도 밀리지 않는다. 웹 프로토타입이 쓰던 방식과 같다. 시계는 그 오디오 시계에서 읽는다.

| 조건 | 40초 동안 시계와 소리의 차이 |
|---|---|
| 보통 | 42.5 → 41.5ms (벌어짐 -1) |
| 게임 스레드 4배 느리게 | 44.0 → 43.1ms (벌어짐 -1) |
| 8배 느리게, 48kHz | 41.2 → 44.3ms (벌어짐 +3) |

벌어지지 않는다. 남은 40ms 남짓의 일정한 차이는 재는 도구의 지연이 섞인 값이고, 기기마다 다른 부분은 박자 맞추기(C)로 맞춘다.

**PC 빌드는 이 길을 쓰지 않는다.** 거기서는 엔진의 믹서가 자기 스레드에서 돌고, 시계는 재생 위치에서 읽는다. 이쪽은 아직 실제 PC 빌드로 재 보지 않았다.

재는 법(웹 빌드를 띄운 뒤):

```bash
node scripts/godot-audio-check.mjs 40
```

```bash
SLOW=4 node scripts/godot-audio-check.mjs 40
```

브라우저의 소리 출력을 가로채 기본 맥박의 클릭이 실제로 나는 순간을 찾고, 게임의 시계가 말하는 박과 견준다.

## 소리를 미리 굽는 이유

GDScript로 실시간 합성을 하면 느리고, 웹에서는 지연도 커진다.
곡은 씨앗에서 전부 정해지므로, 스테이지를 불러올 때 겹마다 루프를 한 번 구워 두고 보통의 반복 재생으로 튼다.
굽는 데는 여섯 겹에 0.3초쯤 걸린다.

## 실행

```bash
godot --headless --path godot --import
```

```bash
godot --headless --path godot -s res://tools/run_tests.gd
```

```bash
godot --headless --path godot --export-release Web ../dist/godot/index.html
```

웹 내보내기에는 4.7.2의 웹 템플릿이 필요하다. `npm run build` 는 `dist` 를 비우므로, 고닷 내보내기는 그 뒤에 한다.
