# 레벨디자인 기록

레벨디자인 세션이 맡는 일: 맵, 기믹 설계와 배치, 보스 패턴, 난이도의 흐름. 세션 사이의 약속은 `docs/handoff/README.md`, 새 구조는 `docs/superpowers/specs/2026-11-18-stage-system-design.md`(승인됨, 고닷에서 바로 짓는다).

표기: **[결정]** 은 기획자가 정한 것, **[까미]** 는 레벨디자인 세션의 제안(바꿔도 됨)이다.

## 기획자의 답 (2026-11-18)

- **순서 없이 모으기를 지키는 법 [결정]**: 어느 악기를 먼저 얻더라도 **각자의 방식대로 통과할 수단**이 있으면 좋다. 또는 **악기 개수를 모아야 열리는 길**도 좋다. 미니 메트로베니아이므로 장르의 정통을 다 지킬 필요는 없다.
- **대시의 거리는 판정과 무관하다 [결정]**: 판정은 대시가 나가느냐에 관한 것이고, 거리는 판정으로 달라지지 않는다. 대신 **킥의 박자(음표 길이)에 따라 거리가 달라질 수 있다.** 예: 저지 클럽의 "쿵 / 쿵 / 쿵 쿵 쿵"에서 뒤의 셋은 대시가 더 짧다. 시스템 세션과 함께 짜 볼 예정.
- **검사기가 "처음 나올 때 하나만 있는가"와 "보스 전에 다시 나오는가"도 확인한다 [결정]**: 보스가 쓰는 공격이 길에서 처음 나오는 곳에는 그 공격 하나만 있고, 보스 전에 다른 위치나 다른 공격과 함께 한 번 더 나온다.

## 기획자의 피드백 (2026-11-18, 1판에 대해)

- **갈래마다 방에 가서 하나씩 얻어 오는 구조는 싫다 [결정]**: 방탈출이나 추리물 같다. 열린 필드, 오픈 구조가 좋다.
- **"모티프" 같은 말은 쉽게 [결정]**: 검증 빌드의 말을 쓴다. 공격 모양 넷(원·고리·빔·장판), 보스 패턴(2~4마디의 공격 묶음).
- **사람이 알아들을 수 없는 표현 금지 [결정]**: "내 자리에 찍힌 것은 두 박 뒤에 떨어진다" 같은 비유를 쓰지 않는다. 누가, 몇 박에, 어떤 크기로, 플레이어가 무엇을 하면 되는지를 그대로 적는다.
- **처음 기획 때 잡은 패턴 감각을 지킨다 [결정]**: 1판이 보스 패턴의 크기와 박을 바꿔 버렸다. 2판은 검증 빌드의 값으로 되돌렸고, 길의 장치는 보스 패턴의 일부를 크기와 박을 바꾸지 않고 반복한다.
- **웹의 역할 [결정]**: 지금의 웹 빌드를 계속 개발해서 **프로토타이핑과, 고닷에 옮기기 전의 레벨 디자인을 하는 곳**으로 만든다. → `workbench.md`

## 기획자의 결정 (2026-11-18, 2판에 대해)

- **보스 무대를 가운데 둔 둥근 필드로 간다 [결정]** ("아주 좋아").
- **악기 구역 사이는 절벽으로 나눈다 [결정].** 검사기가 확인한다: 가운데 필드를 거치지 않고는 다른 구역으로 걸어갈 수 없고, 절벽 폭은 대시(1U)로 건널 수 없다.
- **웹 작업대는 레벨디자인 세션이 만든다 [결정].** `workbench.md` 의 "가" 안. 시스템 세션의 규칙 코드(`src/core/**`)는 읽기만 하고, 작업대는 따로 둔다.

## 웹으로 돌아온 뒤 (2026-11-18)

- **구현은 웹으로 한다 [결정].** 고닷은 멈췄다. 시스템 세션이 2판 설계를 `src/data/stages/stage-01.json` 으로 옮겨 첫 스테이지가 게임에서 돈다.
- **기믹, 배치, 맵 제작은 레벨디자인 세션이 직접 한다 [결정].** 고치는 곳:
  - 첫 스테이지: `scripts/build-stage01.py` 를 고치고 `python3 scripts/build-stage01.py` 로 `src/data/stages/stage-01.json` 을 다시 만든다
  - 새 기믹의 규칙: `src/core/stage/sim.ts` (시스템 세션도 고치는 파일이라 PR 설명에 적어 알린다)
  - 작업대: `workbench.html`, `src/workbench/**`, `tests/workbench/**`
- **판정 규칙 [결정, 2026-11-18 고침: 너무 어려워서].**
  - 회피 대시: 박에서 ±120ms 안에 누르면 대시가 나가고, **대시하는 동안 내내 무적**이다. 엇박에 누르면 나가지 않는다. 거리는 늘 1U.
  - 저스트 회피: 회피를 시작한 때가 나에게 떨어지는 공격의 판정 순간과 ±60ms 안에 겹치면, **다음에 맞히는 공격의 피해가 2배**. 수호자의 회피 통과는 저스트 횟수로 센다.
  - 그래서 박에 맞춘 대시면 어떤 두께의 공격이든 지나간다. 대시 한 번으로 못 넘기는 것은 장판처럼 여러 박 동안 남아서 매 박 판정하는 공격뿐이다.
  - 낭떠러지 틈도 박에 맞춰서만 대시로 건널 수 있다. 틈이 박자를 연습시키는 장치가 된다.
- **땅이 녹아 붙는다 [아트 결정].** 땅 도형이 만나는 자리는 0.75U 범위에서 하나로 녹아 붙는다(`map.blend`). 좁은 틈은 조금 더 좁아진다. 작업대 검사도 게임과 같은 땅으로 계산한다.
- 레벨디자인이 1단계에서 따로 만든 스테이지 데이터 형식은 지웠다. 작업대는 게임과 같은 데이터, 같은 규칙(`src/core/stage`)을 읽는다.

## 맵의 촘촘함 기준 (2026-11-18 기획자 결정)

화면 하나 = 가로 10.7U × 세로 6U 를 기준으로 잰다.

- 악기까지 가는 길에서 걸어서 화면 하나(10.7U)를 지나는 동안 무언가를 **2번 이상** 만난다.
- 아무 공격도 닿지 않고 걷는 구간은 **4박 이하**.
- 악기 구역 하나의 땅은 **화면 3장 이하**.

작업대 검사 "맵이 촘촘한가"가 이 기준으로 잰다. 지금 첫 스테이지는 기준 미달이다(구역마다 화면 9~11장, 아무 일 없는 구간 9~13박, 화면 하나에 1.1~1.4번). 요소 협의가 끝난 뒤 맵을 다시 짠다.

## 따라오는 것 [까미]

- 4/4 챕터에서는 킥과 스네어가 고르게 떨어지므로 대시 거리는 하나다. 첫 스테이지는 **대시 1U**로 짠다(1U = 한 박 동안 걷는 거리, 110 BPM에서 120px).
- 대시 거리는 판정과 무관하게 늘 1U다. 명세 5절의 "빗나간 대시로는 못 건너는 틈(0.6~0.8U)"은 쓸모가 없어졌다. 엇박에는 대시가 나가지 않으므로, 틈과 공격 모두 박에 맞춰 대시해야 넘는다.
- 맵의 모든 거리는 U로 적어 두고, 나중에 킥의 음표 길이로 대시 거리가 달라지면 그 챕터의 데이터만 바꾼다.

## 확인한 것과 확인하지 못한 것

레벨디자인 세션은 게임을 손으로 해 볼 수 없다. 풀 수 있는지는 봇과 검사기로 확인하고, **난이도와 손맛은 확인하지 못한다.** 문서마다 무엇을 어떻게 확인했는지 적는다.
