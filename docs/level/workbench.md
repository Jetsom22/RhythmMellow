# 레벨 디자인 작업대

- 날짜: 2026-11-18
- 만드는 세션: 레벨디자인 (기획자 결정)
- 보는 곳: `/RhythmMellow/workbench.html` (시스템 브랜치에 들어간 뒤), 개발 중에는 `npm run dev` 후 `/workbench.html`
- 다른 스테이지: `workbench.html?stage=이름` (`src/data/stages/이름.json`)

작업대는 게임과 **같은 스테이지 데이터**(`src/data/stages/*.json`)와 **같은 규칙**(`src/core/stage/sim.ts`, `shapes.ts`)을 읽는다. 게임을 고치지 않고, 레벨 디자인에 필요한 것을 더한다: 위에서 내려다보는 지도, 손으로 넘기는 박, 공격이 닿는 범위, 검사 보고서.

## 화면

| 무엇 | 하는 일 |
|---|---|
| 지도 | 끌어서 옮기고, 휠이나 + − 로 확대한다. 땅, 낭떠러지, 다리(닫힌 것은 점선), 장치, 음표 몬스터, 수호자와 대결장, 악기, 공명판, 체크포인트, 시작 위치 |
| 재생과 슬라이더 | 110 BPM으로 돌리거나, 한 스텝씩 넘긴다. 보스 패턴 5개가 끝까지 도는 길이(16마디 이상)만큼 넘길 수 있다 |
| 공격이 닿는 범위 | 각 공격이 닿을 수 있는 칸을 칠한다. 한 종류만 닿으면 그 공격의 색, 둘 이상 닿으면 회색 |
| 다리 다 열기 | 악기와 공명판을 모두 얻었을 때의 다리를 연다 |
| 검사 결과 | 아래 12가지. 문제 항목을 누르면 지도에서 그 위치를 가리킨다. JSON으로도 볼 수 있다 |
| 공격 등장표 | 보스가 쓰는 공격마다, 그 공격을 쓰는 길의 장치·몬스터와 "혼자 %"(닿는 범위 중 다른 공격이 닿지 않는 부분), 수호자, 보스 패턴 |
| 선택한 것 | 지도에서 누른 것의 공격, 패턴, 지금 박. **"이 자리에서 게임 열기"** 로 그 자리에서 게임을 시작한다(`index.html?stage=…&at=x,y`) |

## 검사 12가지

| 검사 | 기준 |
|---|---|
| 보스 패턴이 검증 빌드와 같은가 | 보스 패턴 5개의 박, 표시 길이, 크기, 보스 공명판 위치가 `src/core/game/bossPatterns.ts` 와 같다 |
| 공격 판정이 정박에서만 나는가 | 모든 판정이 킥·스네어 박에 있고, 장치의 한 바퀴 길이가 박의 배수다 |
| 모든 것이 땅 위에 있는가 | 장치, 몬스터, 수호자, 악기, 공명판, 체크포인트, 시작 위치 |
| 악기 구역 사이가 절벽으로 나뉘어 있는가 | 악기가 없을 때 가운데 필드를 거치지 않고는 걷기나 대시(1U)로 다른 구역에 갈 수 없다 (기획자 결정) |
| 보스가 쓰는 공격이 모두 길에 먼저 나오는가 | 원, 고리, 빔, 장판 모두 길의 장치나 몬스터에 있다 |
| 공격을 처음 만날 때 그것 하나만 있는가 | 시작에서 걸어 들어가면, 각 공격이 혼자 닿는 곳을 다른 공격과 섞인 곳보다 먼저 만난다 |
| 보스 전에 다시, 다른 공격과 함께 나오는가 | 공격마다 길에서 2번 이상, 다른 공격과 같이 닿는 곳이 있다 |
| 보스가 쓰는 공격이 수호자에서도 나오는가 | 수호자들이 원, 고리, 빔, 장판을 모두 쓴다 |
| 어느 순서로 모아도 악기 셋과 보스에 닿는가 | 6가지 순서 모두, 다리가 열리는 조건대로 걷기와 대시로 간다 |
| 악기가 없어도 수호자를 통과할 수 있는가 | 수호자의 모든 패턴에 회피 통과(`advance.answered`)가 있다 |
| 공격이 있는 곳마다 8U 안에 체크포인트가 있는가 | 길의 장치와 몬스터마다 |
| 맵이 촘촘한가 | 악기까지 가는 가장 짧은 길에서 화면 하나(10.7U)에 2번 이상 만나고, 아무 공격도 닿지 않는 구간이 4박 이하. 악기 구역 하나가 화면 3장 이하 (기획자 결정). 지금 첫 스테이지는 미달 |

계산하는 법: 필드를 0.5U(절벽 검사는 0.25U) 칸으로 나눈다. 걸을 수 있는 칸은 게임의 `isGround`(도형이 만나는 자리가 녹아 붙은 땅, `map.blend`)로, 공격이 닿는 칸은 게임의 `hits` 로 정한다. 음표 몬스터는 플레이어가 그 거리(`range`) 안에 있을 때 플레이어 자리를 노리므로, 그 거리 전체를 닿는 범위로 본다. 대시는 엇박에 나가지 않으므로 박에 맞춘 대시만 센다(거리 1U).

각 검사가 실제로 문제를 잡는지는 `tests/workbench/checker.test.ts` 가 데이터를 일부러 망가뜨려 확인한다. `tests/workbench/stage01.test.ts` 는 첫 스테이지가 촘촘함을 뺀 11가지를 통과하는지 보고, 촘촘함은 아직 미달인 것으로 적어 둔다(맵을 다시 짜면 바꾼다). 그래서 스테이지를 고쳐 검사를 어기면 `npm test` 가 실패한다.

## 지금 첫 스테이지 (2026-11-18)

검사가 처음 찾은 것과 고친 것:

- 가운데 필드의 음표 몬스터가 드럼·베이스 구역 입구 가까이에 있어서, 고리와 장판 공격을 원 공격과 섞인 채로 먼저 만날 수 있었다. 몬스터를 구역 사이 절벽 쪽(330°, 210°)으로 옮겼다.
- 장치 4개와 옮긴 몬스터 2마리가 체크포인트에서 8U 넘게 떨어져 있었다. 체크포인트를 5개 더했다(구역마다 섞인 곳 옆, 베이스 구역 왼쪽 둑 앞, 가운데 필드 북쪽 둘).

## 다음

- **봇 이동 경로.** 지금 검사는 "닿을 수 있는가"와 "공격이 어디에 닿는가"만 본다. 실제로 박에 맞춰 공격을 피하며 지나갈 수 있는지는 봇이 걸어 봐야 안다. 게임의 `StageSim` 을 그대로 돌려 봇이 각 구역을 지나 악기를 얻게 하고, 그 길을 지도에 그린다.
- **보스 직전의 섞인 길.** 2판 설계에 있던 것(무대를 감아 오르며 공격 두 종류가 함께 나오는 길)이 아직 맵에 없다.
