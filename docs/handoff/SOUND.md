# 사운드 세션 인수인계

맡는 일: **음색, 믹싱, 박자 패턴에 따른 작곡, 전반적인 마스터링.** 먼저 `docs/handoff/README.md` 의 약속을 읽는다.

## 가장 먼저 알 것

- **너는 소리를 들을 수 없다.** 시스템 세션도 못 들었고, 그래서 "숫자로는 맞는데 듣기엔 나쁜" 소리를 여러 번 냈다. 판정은 기획자의 귀다. 네가 할 수 있는 것은 재는 것과, 기획자가 빨리 견줘 들을 수 있게 만드는 것이다.
- **기획자는 브라우저로 듣는다.** 고닷 빌드를 웹으로 내보낸 것(https://jetsom22.github.io/RhythmMellow/godot/)이 유일한 청취 경로다. 시스템 브랜치에 들어가야 올라간다.
- **한 번에 하나씩, 견줘 들을 수 있게.** 음색을 바꿀 때는 이전 것과 번갈아 들을 수 있는 키를 남긴다(지금 B와 L이 그런 키다).

## 볼 것

- 듣는 곳: https://jetsom22.github.io/RhythmMellow/godot/ — 아무 키로 시작, 1~5 겹 켜고 끄기, B 다음 베이스 음색, L 다음 리드 음색, Space 박 맞춰 누르기, C 박자 맞추기. 주소에 `?seed=12`, `?bass=1`, `?lead=2`.
- `godot/README.md` — 고닷 프로젝트의 짜임, 소리를 미리 굽는 이유, 박이 어긋났던 문제와 고친 경위
- `godot/audio/synth.gd` — 목소리(킥, 스네어, 하이햇, 베이스, 리드, 패드)를 만드는 합성. 베이스와 리드는 음색이 넷씩 있다
- `godot/audio/mix.gd` — 믹싱. 설정은 `DESK` 표 하나에 모여 있다
- `godot/core/song.gd` — 씨앗에서 곡을 만드는 규칙
- `docs/tuning-notes.md` 의 "소리에 대한 기획자의 평가"
- `docs/superpowers/specs/2026-11-18-stage-system-design.md` 의 6.2(박자표), 6.3(악기 겹), 10b(챕터와 악기 세트)

## 결정 (기획자가 정한 것. 바꾸지 않는다)

- **소리는 알고리즘으로 만든다.** 샘플이나 녹음이 아니라 합성이고, 곡은 씨앗에서 나온다.
- **악기를 모을 때마다 반복 선율이 한 겹씩 쌓인다.** 겹은 어떤 순서로 쌓여도 곡이 되어야 한다.
- **회피의 기준은 킥과 스네어가 울리는 자리다.** 킥과 스네어는 귀로 분명히 들려야 하고, 박자표가 말하는 자리에 있어야 한다.
- **챕터는 드럼 박자를 중심으로 묶는다.** 스윙, 포 온 더 플로어, 브레이크비트, 저지 클럽, 4/4 킥+스네어는 서로 다른 챕터다. 챕터마다 악기 세트(겹의 소리와 공격 박자)가 있고, 챕터를 깨면 그 세트를 장비로 얻는다.
- **하드 모드**는 깬 스테이지를 다른 챕터의 악기 세트로 다시 하는 것이다. 그래서 어느 챕터의 세트든 다른 챕터의 곡 위에서 소리가 나야 한다.
- 참고작의 소리 감각은 글리피카(Glyphica: Typing Survival)다. 추측하지 말고 찾아본다.

## 기획자의 평가 (순서대로)

1. 첫 음색: 킥, 하이햇, 패드는 나쁘지 않다(장르에 따라 바꿔야 한다). **베이스와 리드는 쓸 수 없을 만큼 나빴다.**
2. 음색을 넷씩 다시 만든 뒤: 각자 쓸 만은 한데 **서로 어울리지 않는다.** "신디를 막 사서 아무 튜닝도, EQ도, 필터링도 안 하고 누른 것 같다." 음역의 문제는 아니다.
3. **베이스는 쭉 깔아주는 소리라 믹싱이 매우 중요하다.**
4. 믹싱을 넣은 뒤: 전보다 낫다. 하지만 **애시드 베이스(`BASS_PRESETS` 의 "acid")는 아예 못 쓴다.** 다른 악기도 믹싱을 더 해야 한다.

## 지금 있는 것

- **목소리 여섯:** kick, snare, hat, bass, lead, pad. 그리고 드럼을 얻기 전에 들리는 기본 맥박 tick.
- **베이스 음색 넷:** sub pluck, round, acid(못 씀), fm thump. **리드 음색 넷:** fm bell, soft pulse, glass, reed.
- **믹싱(`Mix.DESK`):** 목소리마다 EQ 사슬, 크기(타악은 최대치로, 지속음은 평균 크기로), 공통 잔향의 몫, 베이스가 킥 밑으로 물러나는 양. 리드는 패드와 음역이 겹쳐서 한 옥타브 올려 낸다.
- **마스터:** 가벼운 압축 하나. 웹은 `godot/audio/web_audio.gd` 안의 브라우저 압축기, PC는 엔진의 압축기다. 둘의 설정을 같게 맞춰 두었지만 같은 소리라는 보장은 없다.
- **곡 만들기(`Song.generate`):** 단조 펜타토닉, 2마디, 마디마다 화음 뿌리 하나. 드럼은 킥 1·3박과 스네어 2·4박에 꾸밈 하나, 하이햇은 엇박과 16분 일부, 베이스는 뿌리음의 긴 음, 리드는 8분 격자를 떠도는 선율, 패드는 3음 화음. **4/4 하나뿐이고 장르의 구분이 없다.**

재 본 값(씨앗 7, 110 BPM): 드럼 -19, 베이스 -20, 리드 -21, 패드 -27, 하이햇 -43dB(평균). 합친 최대치 1.0.

## 재는 도구

```bash
godot --headless --path godot -s res://tools/dump_wav.gd -- /tmp/out 7 0 0
```

```bash
python3 scripts/analyze-wav.py /tmp/out
```

겹마다 최대치, 평균 크기, 주파수 대역별 에너지 비율이 나온다.

```bash
godot --headless --path godot -s res://tools/run_tests.gd
```

모든 음색이 깨끗하게 구워지는지(소리가 나고, 깨지지 않고, 길이가 같은지) 본다.

## 지켜야 할 제약

- **소리는 미리 굽는다.** 스테이지를 불러올 때 겹마다 루프 하나로 구워서 반복 재생한다. 실시간 효과는 마스터의 압축 하나뿐이다. 그래서 믹싱도 굽는 단계에 들어 있다(`Mix.process`). 플레이 중에 음색이나 템포를 바꾸는 소리는 만들 수 없다.
- **모든 겹의 루프는 길이가 같아야 한다.** 한 샘플이라도 다르면 겹이 서서히 어긋난다. 검사가 이걸 본다.
- **루프의 끝과 처음이 이어져야 한다.** 잔향과 메아리와 필터가 루프를 돌아 이어지게 되어 있다. 새 효과도 그래야 한다.
- **굽는 시간.** 지금 여섯 겹에 웹에서 3초쯤이다. GDScript라 느리다. 효과를 더할수록 늘어난다. 5초를 넘기면 시스템 세션과 이야기한다.
- **웹과 PC에서 같은 소리.** 굽는 단계는 양쪽이 같다. 엔진의 실시간 효과에 기대면 달라진다.
- **`Song.generate` 는 지금 웹 프로토타입과 같은 씨앗에서 같은 곡을 낸다.** 작곡 규칙을 바꾸면 이 일치는 깨진다. 깨도 된다(웹 쪽은 정답지로만 남는다). 다만 깼다는 것을 `docs/handoff/requests.md` 에 적는다.
- **킥과 스네어의 자리는 박자표(`meter`)의 것이다.** 작곡이 마음대로 옮기지 않는다. 장르마다 다른 자리가 필요하면 그건 새 챕터의 박자표이고, 시스템 세션과 함께 정한다.
- **만지지 않는 것:** `godot/audio/mixer.gd`, `godot/audio/web_audio.gd`, `godot/core/beat_clock.gd`. 소리를 내보내는 길과 시계다. 박이 어긋나는 문제를 세 번 만에 잡은 자리다.

## 아직 정해지지 않은 것

- 챕터마다의 장르와 악기 세트. 어떤 박자를 첫 챕터로 삼을지.
- 박자 패턴(킥과 스네어의 조합)에서 곡을 어떻게 지을지: 화음 진행, 선율의 성격, 베이스가 킥과 맺는 관계.
- 곡의 길이. 지금은 2마디 루프다. 보스전은 악구 단위로 진행한다(되풀이될 때 작은 변주가 들어가야 한다).
- 보스전에서 겹이 심화되는 방식(지금 고닷 쪽엔 없다).
- 주선율을 누가 드는지. 지금 설계는 싸우는 동안 보스, 격파 뒤 플레이어다. 기획자는 플레이어도 들 수 있다고 본다.
- 효과음: 대시, 피격, 악기 획득, 판정.
- 스테레오. 지금은 전부 모노다.
- 마스터링의 기준 크기.
