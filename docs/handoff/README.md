# 세션 사이의 약속

이 저장소에서는 세 세션이 나란히 일한다. 서로의 영역을 건드리지 않도록 경계를 정해 둔다.

| 세션 | 맡는 일 | 주로 만지는 곳 | 브랜치 |
|---|---|---|---|
| **시스템** | 게임 규칙, 박자·소리 엔진, 테스트, 빌드와 배포 | `src/core/**`, `src/audio/**`, `src/input/**`, `src/main.ts`, `tests/**`, `.github/**` | `kkami/youthful-hawking-9iej8u` |
| **아트** | 비주얼 시스템, UI/UX, 이펙트, 시안 | `src/render/**`, `src/ui/**`, `index.html`, `public/concepts/**`, `docs/art/**` | `art/visual-system` |
| **레벨디자인** | 맵, 기믹 배치, 보스 패턴, 학습-반복-심화의 흐름 | `src/core/game/world.ts`, `src/core/game/bossPatterns.ts`, `docs/level/**` | `level/gimmick-design` |

## 규칙

- **남의 영역은 고치지 않고 요청한다.** 필요한 것이 다른 세션의 영역에 있으면 `docs/handoff/requests.md` 에 한 항목으로 적는다(누가, 무엇을, 왜, 받아야 할 모양). 급하면 기획자에게 직접 말한다.
- **기준 브랜치는 시스템 브랜치다.** 각자 자기 브랜치에서 일하고, 시스템 브랜치를 향해 PR을 연다. 시스템 브랜치에 들어가야 GitHub Pages(https://jetsom22.github.io/RhythmMellow/)에 반영된다.
- **일을 시작할 때 시스템 브랜치를 먼저 받아 온다.** 규칙과 타입이 바뀌어 있을 수 있다.
- **`npm test` 와 `npm run build` 가 통과해야 PR을 연다.**
- **기획자는 클라우드 세션에서 화면을 직접 볼 수 없다.** 보여 줄 것은 Pages에 올라가야 한다. 시안은 `public/concepts/` 아래에 두면 `/RhythmMellow/concepts/` 로 열린다.
- **결정은 기획자의 것이다.** 문서에 "결정"이라 적힌 것은 바꾸지 않고, 바꾸고 싶으면 먼저 묻는다.

## 지금까지의 결정 (2026-11-18 기준)

- 게임성은 프로토타입으로 검증됐다. 구조: 악기 셋을 모아 곡을 쌓고, 그 곡 위에서 보스와 싸운다.
- 손이 하는 일은 이동, 박자 회피(킥/스네어 박), 악기 전환 셋뿐. 조준 없음. 공격은 든 악기의 박자로 자동(임시).
- 콘텐츠 배치의 원칙은 학습 → 반복 → 심화.
- **챕터는 드럼 박자(킥·스네어의 조합, 장르의 박자)를 중심으로 묶는다.** 스윙, 포 온 더 플로어, 브레이크비트, 저지 클럽, 4/4 킥+스네어는 서로 다른 챕터다. 지금 코드는 4/4 전제.
- **챕터를 다 깨면 그 챕터의 악기 세트를 장비로 얻고, 이미 깬 스테이지를 다른 장비로 다시 할 수 있다(하드 모드).** 지금 만들지는 않는다.
- 팔레트는 챕터마다 바꿔 낀다.
- 스테이지의 구조는 다시 짜는 중이다: `docs/superpowers/specs/2026-11-18-stage-system-design.md` (승인 대기).
- 프로토타입은 웹, 출시는 고닷 이식, 플랫폼은 PC 스팀.
- 비주얼 방향, 색 체계, 예고·여운·피격 표현은 `docs/handoff/ART.md` 의 "결정" 참고.
