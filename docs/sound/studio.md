# 곡 데이터와 작업실

스테이지의 곡을 악보, 음색, 믹싱까지 한 덩어리의 데이터로 다룬다. 음은 그대로 씨앗에서 나온다. 달라진 것은 **게임의 상태마다 어느 겹이 어떤 악보를 어떤 악기와 어떤 믹싱으로 연주할지를 데이터가 정한다**는 점이다.

아래에서 "확인했다"는 자동 검사나 측정으로 본 것이고, 듣기에 좋은지는 아직 아무도 판정하지 않았다.

## 짜임

| 이름 | 뜻 | 코드 |
|---|---|---|
| 악기(`instruments`) | 합성 설정(`p`)과 믹싱 설정(`mix`)의 묶음. 이름으로 부른다 | `godot/audio/voice.gd`, `godot/audio/mix.gd` 의 `apply` |
| 악보(`parts`) | 씨앗에서 음을 뽑는 규칙(`rule`)과 그 매개변수. `roll` 을 바꾸면 그 악보만 다시 뽑는다 | `godot/core/score.gd` 의 `RULES` |
| 장면(`scenes`) | 게임 상태 하나의 편곡. 겹마다 악보와 악기, 페이더를 고르고, 길이(마디)와 장면 전체의 필터를 갖는다 | `Score.bake` |
| 상태(`states`) | 게임 상태 이름과 장면 이름의 짝. 예: `boss.enter` → `intro` | `Score.scene_for` |

기본 곡(`ScoreLibrary.demo()`)에는 장면이 다섯 있다: `explore`, `intro`, `phase 1`, `build`, `drop`. 처음의 음색과 믹싱을 새 구조로 옮겨 적은 것이라, 예전 소리와 비슷하지만 똑같지는 않다.

악보 규칙: `drum`, `hat`, `bass_hold`(긴 뿌리음), `bass_pulse`(짧은 음의 한 마디 음형), `lead_wander`, `arp`, `pad_chord`, `rise`(장면 전체에 걸쳐 올라가는 음형), `written`(손으로 적은 음), `rest`.

- 킥과 스네어의 자리는 `meter.kick`, `meter.snare` 에서 읽는다. 규칙이 옮기지 않는다. 검사가 장면마다 확인한다.
- 악보마다 난수의 흐름이 따로다. 악보 하나를 고쳐도 다른 악보의 음은 바뀌지 않는다.
- 애시드 베이스는 `bass_pulse` 규칙(짧은 음, 악센트, 슬라이드)과 함께 쓰도록 다시 잡았다. 긴 음에는 맞지 않는다.

## 작업실

`godot/studio/studio.tscn`. 웹 빌드에서 주소에 `?studio` 를 붙이면 열리게 하려 한다(진입점은 시스템 세션에 요청해 두었다. `docs/handoff/requests.md`).

- **SCENE**: 들을 장면. **Play / Stop**.
- 왼쪽: 겹마다 켜기, 솔로, 악보 고르기, 악기 고르기(드럼은 킥과 스네어 따로), 페이더.
- 오른쪽 탭
  - **Sound**: 고른 겹의 악기 합성 설정
  - **Mix**: 그 악기의 음량, 잔향, 킥에 눌리는 양, EQ
  - **Part**: 그 겹의 악보 규칙과 매개변수, `roll`
  - **Scene**: 장면의 길이와 필터, 상태와 장면의 짝
  - **Song**: 씨앗, 템포, 음계, 으뜸음, 화음이 되풀이되는 마디 수
  - **File**: 파일로 저장, 글로 보기, 글에서 불러오기, 기본 곡으로 되돌리기
- 아래: 지금 장면의 음과 재생 위치.
- **Keep this** 는 지금 상태를 견줄 기준으로 삼는다. **Hear the kept version** 을 켜면 그 기준을, 끄면 고치는 중인 것을 듣는다. **Back to kept** 는 기준으로 되돌린다.
- 악기와 악보는 여러 장면이 같이 쓴다. 어디서 쓰는지가 이름 아래에 나온다. 한 장면에서만 바꾸려면 **Copy as a new …** 로 사본을 만든다.
- 고친 것은 브라우저에 저절로 남는다. 저장소에 넣으려면 File 탭에서 파일로 저장해 사운드 세션에 준다.

값을 바꾸면 그 겹만 다시 굽고, 다 구워지면 재생 중인 자리에서 바뀐다. 페이더, 켜기, 솔로는 굽지 않고 바로 바뀐다.

## 잰 것 (2026-11-18)

| 무엇 | 값 |
|---|---|
| 겹 하나를 굽는 시간 (4마디, 110 BPM) | 화면 없는 브라우저에서 0.65~1.4초 |
| 슬라이더를 놓은 뒤 소리가 바뀔 때까지 | 약 1초 |
| 처음 장면 하나가 준비될 때까지 (다섯 겹) | 약 7초 (페이지를 불러오는 시간 포함) |
| 한 번 구운 장면으로 돌아가기, 기준과 번갈아 듣기 | 약 0.5초 |
| 장면 다섯 전부를 굽는 시간 (PC, 편집기 실행 파일) | 17초 |
| 브라우저 출력 (explore, 다섯 겹) | 최대 0.88, 평균 -14.9dB |

기획자의 기기에서는 다를 수 있다.

필터와 잔향이 루프의 이음매를 맞추려고 루프 전체를 한 번 더 돌던 것을, 끝부분만 돌게 줄였다(`Mix.SETTLE`, 잔향은 1.2초). 예전 화면의 굽는 시간도 2.9초에서 2.0초로 줄었다. 소리의 차이는 재지 않았다.

## 아직 안 되는 것

- **장면이 넘어가는 순간.** 작업실은 장면을 고르면 구워지는 대로 바꾼다. 마디의 경계에 맞추지 않고, 새 장면의 첫 마디부터 시작하지도 않는다(전체 시계의 자리에서 이어 간다). 빌드업에서 드롭으로 넘어가는 느낌은 아직 들어 볼 수 없다.
- **한 번만 연주하는 장면.** 모든 장면이 루프다. 빌드업처럼 한 번 지나가는 장면, 그 안에서 필터가 열리는 움직임은 없다.
- **보스 패턴에 따른 모듈.** 상태와 장면의 짝만 있다. 패턴마다 겹을 갈아 끼우는 규칙은 보스 데이터의 모양이 정해져야 한다.
- **게임 화면.** 실험 화면(`main.gd`)은 예전 길(`Song`, `Synth.render`)을 그대로 쓴다. 곡 데이터를 게임이 읽는 일은 시스템 세션과 정한다.
- **손으로 음 찍기.** `written` 규칙은 데이터로만 쓸 수 있고, 화면에서 찍을 수는 없다.
- 스테레오, 효과음, 마스터링의 기준 크기.

## 검사

```bash
godot --headless --path godot -s res://studio/check.gd
```

모든 장면의 모든 겹이 길이가 맞고, 소리가 나고, 넘치지 않고, 킥과 스네어가 박자표의 자리에 있고, 저장했다 불러와도 같은지 본다. 뒤에 폴더를 주면 겹마다 WAV로 써 준다(`-- /tmp/out`).
